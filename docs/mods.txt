MODIFICATIONS LOG - branch `purge-sqlite-workerd` (dude fork of opencode)

This file records the SQLite/workerd -> PostgreSQL migration plus the follow-up
cleanup performed on this branch. Nothing here is committed yet: the whole set
is uncommitted working-tree state on top of `133b1ebfaf` (== origin/dev).

Note: parts of the working tree were already modified before this record (e.g.
the Discord de-branding of README/i18n and the new release workflow). Only the
database migration, test isolation, branding plumbing and the SQLite vestige
cleanup described below were authored/verified here.

--------------------------------------------------------------------------------
1. SCOPE
--------------------------------------------------------------------------------
- Replace the SQLite/workerd storage stack with PostgreSQL.
- Keep every shared call site working (the fork uses `db.select()...get()`,
  `.all()`, `.run()` everywhere; PostgreSQL drizzle only ships `.execute()`).
- Preserve SQLite runtime semantics where call sites/expected output depend on
  them (byte-order text comparison, NULL ordering, JSON helpers, counts).
- Give the test suite per-test isolation again (SQLite used one temp file/test).
- Remove every functional trace of SQLite/workerd.

3. POSTGRES SEMANTICS: restorations required by the port
--------------------------------------------------------------------------------
- COLLATE "C" for byte-order text ranges (locale collation is pt_BR.UTF-8 here).
    pg-schema.ts: `inDirectorySubtree(column, directory)` =
      `column collate "C" >= dir and column collate "C" <= dir || U+FFFF`.
    project.ts (project adoption) and session/projector.ts (Worktree.Resolved
    session repointing) now use it. Before: locale collation sorted U+FFFF
    before "/" so nested sessions/projects were never matched.
    kv.ts: KV prefix scan pins COLLATE "C" on the bounds and ORDER BY; before,
    `KV.scan` returned nothing and background-job recovery was empty.
- NULL ordering: SQLite sorts NULL first on ASC, Postgres last.
    credential.ts `all`/`list` order `active asc nulls first`.
- SQLite JSON helpers (Postgres has no json_set/json_remove/json_each):
    session/stats.ts: `json_each(msg.data,'$.content')` ->
      `jsonb_array_elements(msg.data -> 'content') AS content(value)`;
      numeric extracts cast `::double precision`; `count(*)` cast `::int`
      (Postgres returns BigInt);
      camelCase aliases quoted (`AS "sessionID"`, `AS "timeCreated"`, ...)
      because Postgres folds unquoted aliases to lowercase.
    tests: `json_set(json_remove(...))` -> `jsonb_set(data - 'native', ...)`;
      `json_set(data, '$.content[0]...')` -> `jsonb_set(data, '{content,0,...}')`.
- Raw SQL SQLite-isms:
    tests/session-projector: `INSERT OR IGNORE` -> `ON CONFLICT DO NOTHING`.
    credential test legacy insert: boolean column written as `TRUE` not `1`.
    bus.ts: `max(a,b)` -> `greatest(a,b)`; dropped sqlite `{ behavior:"immediate" }`
      transaction config from `db.transaction(...)`.
    workspace/sql.ts: `sqliteTable` -> pg `table`, `text({mode:"json"})` -> `json`.
- workspace.ts idle monitor: reads the persisted binding from an in-memory Ref
  (`connection.binding`, updated by `saveBinding`) instead of an async DB read,
  so `TestClock.adjust` completes the suspension synchronously.
- Timestamp columns are `double precision` so epoch-ms > 2^31 work.

4. TEST INFRASTRUCTURE: per-schema isolation
--------------------------------------------------------------------------------
Postgres is one shared database; the old suite relied on one temp SQLite file
per test. Now:
  packages/core/test/lib/effect.ts (`testEffect`/`it`/`live` harness)
    - Each test gets `OPENCODE_DATABASE_SCHEMA=oc_test_<uuid>`, created before
      the body and dropped (with any `<schema>%` siblings) after it, so state
      outlives multiple layer builds inside one test but never leaks out.
    - Real event-loop drain AFTER each `TestClock.adjust`/`setTime` (wrapping the
      TestClock service): async Postgres writes triggered by a clock jump would
      otherwise land after the assertion.
    - `OPENCODE_DATABASE_IDLE_TIMEOUT` raised so TestClock jumps don't close
      pool connections.
    - Exported `settle` helper for tests that must await background async work.
  packages/core/test/fixture/database.ts
    `isolatedDatabase()` -> `Database.configured({ schema: '<env>_target' })`,
    replacing the old "second SQLite file" pattern
    (session-create, session-view, repository-cache now use it).
  Test-side adaptations: shell-parse empty-wasm stub; session-projector reads
    jsonb as an object (no JSON.parse); session-native/session-runner jsonb_set;
    preload/session-create/view/repository-cache; integration + location-activity
    settle; clock-settle fixed LocationActivity eviction.
